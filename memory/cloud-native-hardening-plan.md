# Cloud-native hardening plan (session notes)

Transitory session notes, not durable project guidance — deliberately **not** wired into
`CLAUDE.md`/`AGENTS.md`, so it won't get auto-loaded into every session's context. Kept here
(rather than only in local `~/.claude` memory) so it survives switching laptops, since Claude
Code's local memory is machine-local and doesn't sync.

## Why this work exists

`docs/platform-architecture.md` (added 2026-07-04, status "whiteboard / pre-implementation") specs converting this repo's single-user Python CLI content pipeline into a multi-tenant SaaS: Java/Spring Boot API + Temporal orchestration + Postgres/MinIO + k8s, with the existing `scripts/` pipeline scripts (`research.py`, `script.py`, `repurpose.py`, `analytics.py`, etc.) promoted into Temporal-activity-backed Python workers. None of that migration is built yet.

This work is proactively hardening the *current* Python scripts against the cloud-native issues that migration will surface (retries, observability, idempotency, statelessness) so there's less rework later — not building the migration itself.

**How to apply:** When resuming this work, don't jump to implementing the Temporal/Java/Postgres side — stay scoped to hardening the existing `scripts/` Python code. Read `docs/python-refactor.md` first; every pattern established so far (gateway, structured logging, provider-calls helper, repository pattern) is documented there in detail — that doc is the living source of "how we build things here," this file is just the roadmap/todo state.

## Already done

- **API gateway** (`scripts/gateway/`): retry w/ exponential backoff + jitter, per-host circuit breaker, both config-driven (`scripts/config/gateway.toml`). All provider HTTP calls route through it via `scripts/providers/http.py`.
- **Idempotency keys on the gateway**: POST/PATCH calls get a UUID `Idempotency-Key` header, generated once per logical call and reused across retries — solves *retried-HTTP-attempt* duplication only (not whole-script-rerun duplication, see open todo below).
- **Structured logging** (`scripts/utils/logging.py`): JSON-lines to stderr, separate from Rich's stdout human output. Wired into gateway retries/circuit-breaker transitions (state changes only, not every call).
- **Shared call helpers** (`scripts/providers/calls.py`): `call_ai(name, prompt, channel_name, on_error=...)` replaced 4 duplicated `call_claude` functions across `analytics.py`/`research.py`/`repurpose.py`/`script.py`; `youtube_get(...)` replaced duplicated YouTube Data API calls.
- **Prompt config** (`scripts/config/prompts.toml` + `scripts/utils/prompts.py`): each script's Claude system prompt composed from shared channel voice + per-script persona/rules, instead of hardcoded f-strings.
- **Repository pattern for the call store** (`scripts/store/repository.py`): `CallRepository` ABC + `SQLiteCallRepository`, decouples `calls.py`/`report.py` from raw SQLite. Deliberately did *not* build a separate API/service layer for this — premature until there's an actual second process consuming it (that's the already-scoped Postgres+Spring-Boot migration in platform-architecture.md).

## Done since last update

1. **Fixed backlog.md double-append idempotency.** Added `scripts/utils/markdown.py::append_once(path, content)` — hashes the content internally (`sha256(content)[:12]`) and writes an `<!-- signal:<hash> -->` marker after the appended block, skipping the write if that marker already exists. Both `research.py::append_to_backlog` and `analytics.py::append_feedback_to_backlog` just call `append_once(backlog, "\n".join(lines))`, replacing the old unconditional `open(..., "a")` writes. Originally had callers compute their own `key = hashlib.sha256(...)` and pass it in alongside `content` — collapsed that into `append_once` itself once it was clear both call sites hashed the content the same way, so neither script needs `hashlib` anymore.

2. **Added a unit/mock test suite.** Framework: pytest (`requirements-dev.txt`, `pyproject.toml` sets `pythonpath = ["."]` + `testpaths = ["tests"]` so `from scripts...` imports work with no sys.path hacks). `make install-dev` / `make test` added to the Makefile. Covers the gateway (retry policy, circuit breaker state machine, `send()` integration incl. the breaker-opens-mid-retry short-circuit), `append_once`, `SQLiteCallRepository`, and `call_ai`/`youtube_get`'s `on_error` modes. `tests/conftest.py` has autouse fixtures resetting module-global state (circuit breakers, event sink, provider instance cache) between tests and stubbing `time.sleep` so retry-backoff tests run instantly. No mocking library beyond stdlib — monkeypatch + fakes throughout, per the user's pytest choice (not pytest-mock/responses). This suite kept growing as todo 3 below added new modules — see file list in that item.

3. **Added pub/sub event hooks**, following the exact provider-plugin pattern (registry + `<KIND>_PROVIDER` env var, like `get_provider("ai")`):
   - `scripts/providers/base.py::EventPublisher` (ABC, `publish(event, payload)`), registered as kind `"events"` with default `"console"` in `registry.py`.
   - `scripts/providers/console_events.py::ConsolePublisher` (default) — prints via `scripts.utils.console.rprint`.
   - `scripts/providers/kafka_events.py::KafkaPublisher` — real implementation using `kafka-python` (now a live dependency in `requirements.txt`, not commented-out-future like the other optional SDKs). Config in `scripts/config/providers.toml`'s `[kafka]` section. **Important gotcha found during verification:** `KafkaProducer` auto-negotiates the broker API version at construction by default, which blocks on a real network round-trip — set `api_version` explicitly in config to skip that. Similarly `send()` can block far longer than expected against an unreachable broker unless `max_block_ms`/`request_timeout_ms` are set — verified end to end against an actually-unreachable host: construction returned in 0.14s, `publish()` failed cleanly as `ProviderError` at exactly the configured 5s bound (not a hang).
   - `scripts/providers/events.py::publish_event(event, payload)` — thin helper, swallows+logs any failure (a broken/unconfigured subscriber must never break the caller) — and `wire_gateway_events()`, which installs itself as the gateway's circuit-breaker event sink (see below).
   - **Dependency-direction constraint that shaped this:** `scripts/gateway/` must never import `scripts/providers/` (established rule, see `docs/python-refactor.md`). Circuit breaker transitions need to publish events, so `scripts/gateway/circuit_breaker.py` got a generic `set_event_sink(fn)`/`_publish()` seam (mirrors `http.py`'s existing `_recorder`/`set_recorder` pattern for the call store) instead of importing `scripts.providers.events` directly. `scripts/providers/__init__.py` calls `wire_gateway_events()` at import time (lazy import, guarded by `EVENTS_LOG` env var, same best-effort-try/except style as the existing store auto-enable right above it).
   - Wired to publish at three points (the scope agreed with the user): circuit breaker `circuit.open`/`circuit.half_open`/`circuit.closed` (only on actual state changes, same rule as the existing logging); `scripts/providers/http.py`'s `_record()` now also calls `publish_event("provider.call.completed", merged)` unconditionally (separate from the optional call-store recorder — http.py is a peer providers-layer module so no seam was needed there, direct import is fine); `research.py`/`analytics.py` publish `backlog.appended` or `backlog.skipped_duplicate` right after their `append_once()` call, based on its return value — deliberately *not* wired inside `markdown.py` itself, to keep that helper provider-agnostic (same reasoning as why `utils/` doesn't depend on `providers/` anywhere else).
   - Tests: `tests/test_providers_events.py` (console + `publish_event` + `wire_gateway_events` + `KafkaPublisher`, with a fake `kafka` module injected via `sys.modules` so the suite doesn't need a real broker), extended `tests/test_gateway_circuit_breaker.py` (event sink fires on transitions, no-op when unset, swallows sink exceptions), `tests/test_providers_http_events.py`, `tests/test_backlog_events.py`. `tests/conftest.py` gained fixtures to reset the event sink and the provider registry's instance cache between tests. Full suite: 55 tests, ~0.07s.
